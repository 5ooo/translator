# 安装与配置

## 安装

当前验收平台为 Ubuntu 24.04 x86_64、Python 3.12.12、uv 0.9.10。最低硬件和磁盘要求未单独测定。PLaMo 自动安装的运行器支持 Linux x86-64，CPU 可运行，Vulkan 显卡为可选。

先安装 uv，在项目目录检查环境并安装：

```bash
./scripts/check_env.sh
./install.sh
```

`check_env.sh` 只检查系统、工具和磁盘信息，不下载或安装文件；缺少 uv 或无法自动补齐系统工具时退出非零。首次安装通常需要联网。脚本默认使用 uv 将 Python 3.12.12 安装到项目 `.runtime/python/`，在 `.venv-uv/` 中安装锁定的 Python 依赖，并下载和校验 Argos 中英双向模型。PLaMo 需要[单独安装](模型选择.md)。

如果系统缺少 Tesseract 或剪贴板工具，脚本会通过 apt-get 下载系统包，并解压到项目 `.runtime/system/`，不使用 sudo。系统工具已可用时，脚本会复用它们。Linux 共享库、显卡驱动和桌面显示服务由系统提供。

脚本在 `~/.local/bin/ts` 创建指向项目 `bin/ts` 的链接，已有其他同名命令时不会覆盖。确保 `~/.local/bin` 在 PATH 中；不激活虚拟环境也能使用 `ts`。

重新运行脚本会复用已有可用虚拟环境及模型。首次创建虚拟环境时可设置 `TS_PYTHON` 选用其他解释器；已有环境不会因该变量自动更换。移动项目目录后，需要重建虚拟环境并更新命令链接，因为环境包含项目绝对路径。

## 离线运行与重建

模型和依赖安装完成后，语言识别、OCR 和翻译不需要联网。PLaMo 使用自己启动的本机运行器。

Argos 模型的文件名、来源和 SHA256 记录在 `scripts/models.json`。已有 `.argosmodel` 文件可离线导入：

```bash
ts --install-model ./translate-en_zh-1_9.argosmodel
ts --install-model ./translate-zh_en-1_9.argosmodel
```

也可将校验通过的模型包放入 `.runtime/downloads/`，安装脚本会复用。离线重建整个环境还需要提前准备 Python、依赖缓存、系统工具和模型；仅复制 Git 仓库不足以完成离线安装。PLaMo 离线安装方法见[模型选择](模型选择.md)。

## 项目目录

| 目录 | 内容 |
| --- | --- |
| `src/ts/`、`bin/`、`scripts/` | 程序、入口和安装脚本 |
| `docs/`、`tests/` | 文档和自动化测试 |
| `.runtime/python/`、`.venv-uv/` | 项目本机 Python 及依赖 |
| `.runtime/data/` | Argos 和 PLaMo 模型 |
| `.runtime/tools/` | PLaMo 运行器 |
| `.runtime/system/` | 项目内的 OCR、语言包和剪贴板工具 |
| `.runtime/config/`、`.runtime/downloads/` | 本机模型设置和已下载的 Argos 包 |

`.gitignore` 排除 `.runtime/` 和 `.venv-uv/`。提交源码不会包含模型、运行器、虚拟环境或本机配置。`XDG_DATA_HOME`、`ARGOS_PACKAGES_DIR`、`TESSDATA_PREFIX` 和 `TS_PLAMO_MODEL` 等环境变量可以覆盖默认位置。

## 运行与停止

在交互终端运行 `ts`，或从项目目录运行 `./bin/ts`。这是一次性命令，不需要单独启动服务。等待时可按 `Ctrl+C` 中断；PLaMo 专用运行器随命令结束，不需要单独停止脚本。

结果写到 stdout，错误和交互状态写到 stderr，程序不维护独立的运行日志文件。

## 自检与故障排查

```bash
ts --check
ts --check --model plamo
TS_REQUIRE_PLAMO=1 ./scripts/test.sh -q
```

自检检查资源是否存在；完整测试包含真实 OCR 和离线推理。设置 `TS_REQUIRE_PLAMO=1` 时，缺少 PLaMo 会使测试失败。测试和当前机器的验证范围见[测试报告](测试报告.md)。模型来源及分发许可见[第三方许可](第三方许可.md)。

如果无参数 `ts` 没有读取剪贴板，可用 `type -t ts` 检查当前 shell 是否找到了程序文件。若同名 shell 函数遮蔽了程序，检查该函数后可执行 `unset -f ts`，或直接运行项目内的 `bin/ts`。还需确认当前终端属于有剪贴板的 X11 或 Wayland 会话。
