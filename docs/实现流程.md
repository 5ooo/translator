# ts 实现与验收流程

## 工程与设计

1. 检查现有代码与修改，保存逐文件哈希，修改前后比较，避免覆盖无关内容。
2. 明确自然语言全部互译的规则，保留已有输入、OCR、文本与引擎模块边界。
3. 通过独立设计比较选择有序原文片段方案，修复保护规则，并以换行文本块代替句点分句。
4. 对已复现的普通大写英文、代词 I、中文相邻标识符、中文路径、自然语言命令前缀和小数添加失败回归，再实现修复。
5. 使用真实模型发现并修复英文译文与技术片段之间缺少空格的问题。

模型选择只保留 `argos` 和 `plamo`。首次安装默认 Argos；已保存的 PLaMo 设置保持不变。PLaMo 使用经校验的模型与本机私有运行器，验证其进程和回环连接后才发送输入。清理旧模型时先迁移该校验、移除旧入口和专属文件，再测试两种模型的切换及真实离线推理。

## 环境安装

在项目目录运行：

```bash
./install.sh
```

安装脚本默认通过 uv 将 Python 3.12.12 放入 `.runtime/python`，再使用 `.venv-uv` 和 `requirements.lock` 安装依赖。OCR 与剪贴板工具缺失时，脚本将其解包到 `.runtime/system`。Argos 模型通过官方地址下载并校验 SHA256；PLaMo 按模型选择文档单独安装。安装建立 `~/.local/bin/ts` 链接，已有其他命令时拒绝覆盖。

模型、环境与本机工具不提交版本控制。Python 环境位于 `.venv-uv`。安装需要网络，翻译运行不需要网络。部署脚本可重跑，复用已安装内容。

## 强制真实验收

```bash
ts --check
TS_REQUIRE_PLAMO=1 ./scripts/test.sh -q -rs
ts 'Hello world.'
ts '这是一项测试。'
printf 'Hello.\n你好。' | ts
ts --image '/path/to/mixed.png'
```

测试脚本设置 `TS_REQUIRE_INTEGRATION=1`；命令额外设置 `TS_REQUIRE_PLAMO=1`。真实资源缺失必须失败，不跳过。语言识别、双向 Argos 推理与 OCR 测试在禁止 Python socket 连接和 DNS 解析的条件下执行；PLaMo 测试仅允许回环连接。

## 剪贴板验收

从独立创建的测试显示器中执行验证，避免覆盖日常桌面剪贴板。先准备 Xvfb 或带输入 seat 的 Weston 测试会话，再运行：

```bash
./bin/python scripts/verify_clipboard.py --backend x11 --display :198
./bin/python scripts/verify_clipboard.py --backend wayland --display ts-nested-test --runtime-dir /path/to/test-runtime
```

该脚本分别写入文字和中英混合截图，从交互式终端 stdin 运行无参数 ts，要求其输出与显式文字或图片输入相同。它使用真实桌面协议和翻译模型。无输入 seat 的 headless Wayland 会话不适合作为剪贴板验收环境。

实际桌面日常使用时，复制文字或截图后从该桌面会话的终端运行 ts。空 stdin 管道不会进入剪贴板。

## 交付检查

在项目外的新登录 shell 确认 ts 命令可解析；用真实双向输入、图片、管道和参数优先级验证结果。再次执行安装脚本和完整测试，确认部署可重复且保留原有其他文件。最终证据与剩余限制记录在 `测试报告.md`，部署决策与运行记录保存在 `.runtime/audit`。

## 交互显示验收

完整测试包含纯文本兼容、TTY 能力、NO_COLOR、TERM=dumb、--plain、窄屏字面文本、错误及中断清理。发布前还须通过实际伪终端执行已安装的 ts，检查中文、长 URL、图片双段、动画清除和光标恢复；剪贴板测试使用独立显示会话。静态原型不替代实际 CLI 验收。
