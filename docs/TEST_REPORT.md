## 2026-11-23 Docker 常驻模式

在 Ubuntu 24.04 x86-64、Docker 28.5.1 的隔离项目中运行 `TS_REQUIRE_PLAMO=1 TS_PLAMO_DEVICE=cpu ./scripts/test.sh -q -rs`，结果为 **301 passed**，包括真实 OCR、语言识别和两种模型的本地推理。

在临时容器中验证了 `--network none`、只读根文件系统、服务预热、两个模型的中英翻译与切换、混合文字和代码/URL 保留；与本地 CPU 模式的八组结果一致。隔离 X11 会话中的文字和图片剪贴板验证通过。停止容器时命令明确报错；重启后立即运行命令会等待预热并完成翻译。重装测试确认新容器就绪后才替换旧容器。

五组 72～76 字符英文短文本交替测速：宿主本地模式中位数 2.49 秒（2.42～2.55 秒），Docker CPU 常驻模式中位数 0.38 秒（0.38～0.40 秒）。宿主使用 NVIDIA Vulkan，容器使用 CPU；两种设备的五组译文有四组完全相同，另一组措辞不同、含义一致。这是本机短文本结果，不代表长文或其他机器。

本机 Docker 的 NVIDIA 运行时无法启动，已验证安装器提示并回退 CPU；Docker GPU 推理、rootless Docker 和 Docker 模式下的 Wayland 剪贴板尚未实测。
