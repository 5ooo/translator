# ts 需求规格

## 目标与范围

ts 是 Linux 离线终端中英翻译工具。翻译与语言识别都在本机执行。图片先经 Tesseract `eng+chi_sim` 提取文字，再与直接输入的文字进入同一处理流程。安装依赖和获取模型属于部署阶段，运行时不得刷新索引、下载模型或调用在线翻译。

## 输入规则

输入优先级固定为显式参数、非终端 stdin、交互终端剪贴板。

- `ts 'Hello world'` 把位置参数连接为文字。单个位置参数若为已存在的图片文件，则执行 OCR。
- `ts --text 'hello.png'` 强制作为文字。`ts --image './a b.png'` 强制作为图片路径。
- `printf 'Hello' | ts` 读取 UTF-8 文字。单个已存在图片路径也可经 stdin 输入。空管道报错，不退回剪贴板。
- 无显式输入且 stdin 为终端时读取剪贴板。优先读取支持的图片 MIME，再读 UTF-8 文字。文字中的单个图片路径也可进入 OCR。
- Wayland 使用 `wl-paste`，X11 使用 `xclip`。同时存在两个显示环境时优先 Wayland，失败后尝试 X11。只有文字类型时才读取文字，不把任意二进制当作文字。
- 支持 PNG、JPEG、TIFF、BMP、WebP、GIF。由 Pillow 解码后转成 PNG 交给 Tesseract。多帧图片只处理第一帧。
- 显式图片不存在、图片损坏、剪贴板为空、缺少工具或语言包时给出中文错误。

## 识别与翻译

所有自然语言片段调用同一个离线 langid 模型，识别候选限制为中文和英文。英文译中文，中文译英文。数字、标点和受保护片段无需调用翻译模型。

先隔离 Markdown 围栏代码、缩进代码、行内代码、明确的 shell 命令行、URL、绝对与相对路径、Windows 路径、已列入词表的技术缩写、驼峰与下划线标识符。技术片段逐字保留，不发送给识别或翻译模型。例外：整段输入仅为 `grab_box` 这类由小写英文单词和下划线组成的独立词组时，先把下划线转换为空格，再按普通文字离线识别与翻译。若需保留这个标识符，可使用反引号；缩进代码、命令、函数调用、赋值、路径及正文内的标识符仍然保留。ASCII 标识符紧邻中文时仍受保护，例如 `检查API和foo_bar及getValue`。

shell 保护要求提示符、已知子命令、选项或脚本文件参数。`git status`、`python -c 'print(1)'`、`python tool.py`、`ls -la` 受保护。`python is easy to learn` 和 `git is useful` 属于自然语言。`sudo` 本身不足以确认后续内容是命令。无法可靠识别的裸代码和命令使用反引号或代码围栏。

缩写词表包含 API、GPU、CUDA、ROS、ROS2、SLAM、OTA、RGB、MD5、IMU、G1 等技术用语，定义于 `text.py`。大小写本身不能区分缩写与自然语言。`I`、`HELLO WORLD` 和未入词表的普通大写单词参与翻译。未入词表且没有标识符特征的缩写也可能参与翻译，不承诺语义分类完全准确。

路径组件支持中文，例如 `/home/张三/report.txt`、`C:\Users\张三\report.txt` 和 `资料/报告.txt`。受支持的文件扩展名可确定后接中文正文的边界。无明确结尾的 `/tmp/资料然后打开` 存在歧义，整体保留为路径，不拆译其中的中文。路径中的空格、句末标点或模糊边界使用反引号明确标记。URL 保持现有 ASCII 地址规则，不扩展为任意 Unicode 地址解析器。

自然语言按换行分块，不按句点拆句。`The value is 3.14, e.g. a sample.` 整段交给模型。单块内混合中英文时，对不同文字系统的连续片段分别识别与翻译。例如中文说明中的普通英文短语也译为中文，而 API 等缩写保持原样。内部空格保留在片段中，行首行尾空格与换行原样保留。中文译成英文后，正文与保护片段之间若缺少英文词边界，则补充空格；保护片段内部不变。标点随自然语言交给模型处理，不要求译文标点逐字相同。

保护片段两侧分别翻译会损失部分上下文，这是精确保留技术内容的取舍。短词语言识别与机器译文可能不准确；本项目不承诺人工翻译质量。超长自然语言片段在空格附近切为最多 400 字符的小块，避免推理截断。

## 模型与命令行为

只提供本地 `argos` 和 `plamo` 两种模型，均支持中英双向。Argos 两个方向的模型须分别安装；PLaMo 使用一个 Q4_K_M GGUF 模型与本机运行器。首次安装默认 Argos，用户可用 `ts --set-model 名称` 保存选择，或用 `ts --model 名称` 临时指定；模型不可用时明确报错，不自动切换。

`ts --models` 显示速度优先和效果优先两行，在当前模式前显示 `*`，并在支持颜色的终端中突出显示。模式不可用时提示，不显示模型名称。`ts --check --model 名称` 检查所选模型、OCR 和公共依赖，缺失时退出 1 并说明原因。`ts --install-model file.argosmodel` 只安装指定的本地 Argos 包。

纯文本模式下，文字输入成功时 stdout 只含译文。图片输入成功时 stdout 先输出 `原文：` 和 OCR 原文，空一行后输出 `译文：` 和译文。此规则覆盖显式图片、自动识别的图片路径、stdin 图片路径、剪贴板图片及剪贴板文字中的图片路径。纯文本模式下 OCR 原文的空白与换行原样保留，仅在末尾缺少换行时补齐段落边界。纯文本模式下 `--text` 只输出译文，即使文字是已有图片路径。每次成功处理图片只执行一次 OCR，原文与翻译使用同一份识别结果。

交互终端对文字和图片均显示“原文：内容”和“译文：内容”，标签与内容同一行；末尾多余换行不显示，正文内部换行保留。原文因内部换行或终端宽度而显示为多行时，在译文前加入一个空行；原文只有一行时不加入空行。等待时用一行动画显示真实阶段，不展示推算的百分比，完成、出错与中断时清除。stdout 重定向、`NO_COLOR`、`TERM=dumb` 或 `--plain` 使用原有纯文本格式；动画还要求 stderr 连接终端。

错误写 stderr，不输出部分原文或译文。业务错误退出 1，命令用法错误退出 2，中断退出 130。不得执行输入中的命令，不修改剪贴板，不保留 OCR 临时图片，不覆盖用户文件。

## 验收范围

自动化测试覆盖输入优先级、图片路径、双后端剪贴板 MIME、OCR 参数及错误、统一语言识别、混合分段、技术内容保留、本地模型缺失、CLI 输出与退出码。集成测试执行真实 langid、Tesseract 和双向 Argos 推理，并在 Python 层禁止网络连接；设置 `TS_REQUIRE_PLAMO=1` 时强制验证 PLaMo 的真实本地推理，允许其回环连接。桌面剪贴板须在真实 X11 和 Wayland 会话另行验收。测试报告必须区分替身测试和真实推理。

## 直接可用的部署验收

优先用 uv 安装完整 Python 环境。安装阶段允许联网下载系统包和模型，运行阶段完全离线。安装完成后在项目外的新终端直接运行 ts，无需激活虚拟环境。ts --check 必须通过，真实双向翻译、图片 OCR 后翻译、X11 与 Wayland 独立会话中的文字和图片剪贴板均需实际验证。
